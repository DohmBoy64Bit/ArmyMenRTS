# Operating rules for all agents

1. The goal is a source-built, byte-identical copy of the pinned Steam amrts.exe. Credit requires independent compilation and comparison. Only compare the complete executable to claim completion.
2. Read the current rules packet before taking action on an assignment. It contains AGENTS.md, these rules, WORKFLOW.md, ORCHESTRATOR.md, RUNNERS.md and README.md. Every worker gets it on every attempt, including retries, across Codex, Pi, OpenCode and API slots. The lead runs `python workflow.py rules` at batch start and after every three newly integrated functions. Failed experiments do not count.
3. The scheduler assigns the shortest eligible function first, breaking ties by RVA and then job ID. An unmet prerequisite or active lease makes a job ineligible. Multiple independent jobs may run at once. Only the holder of the current attempt token may submit. Work only inside the assigned range and directory. If a boundary overlaps another assignment, return it to the lead for reconciliation.
4. Use REA for target discovery, function boundaries, instruction inspection and other reverse-engineering decisions. Every worker opens the pinned executable in an isolated REA session, calls read_function_instructions for the leased entry VA, and saves the returned Evidence JSON as rea-observation.json at the checkout root. Use the equivalent REA CLI instruction operation when MCP is unavailable. Record the returned evidence ID and an observation that supports the reconstruction in the function's evidence Markdown. Escalate an unavailable provider or uncertain boundary for review.
5. The lead reviews the source and builder. Integration independently runs the pinned REA CLI on the same entry, checks the target digest and inclusive function range, compares the instruction listing, then reproduces the compiled bytes. Provide Node.js, npx and the working REA native provider on the integration machine. Keep raw REA output private. Shared headers, neighboring functions and linker changes belong to the lead. Read-only verification of another worker's result confers no ownership of its assignment.
